背包系统 类字段与功能细化设计
基于《背包系统设计文档》v0.3 的细化  |  2026年11月4日
本文对八个核心类及支撑类型逐项细化字段与功能，作为实现与评审依据。类型缩写：R = InventoryResult（统一结果）。位置统一使用 Vector2i，矩阵左上角为 (0,0)，x 向右、y 向下；访问矩阵使用 cells[y][x]。标注“建议/待细化”的条目为尚未定稿的落地策略。

1 ItemConfig（静态物品定义）
沿用现有 Script/Config/Model/ResourceManager/ItemConfig.gd 的字段名，避免破坏现有资源。ItemConfig 为共享静态 Resource，运行时不修改共享配置。
1.1 字段设计
[TABLE 13 rows]
字段 | 类型 | 来源 | 默认值 | 说明与约束
ItemID | String | 现有 | — | 物品唯一标识，作为 ItemInstance.config_id 的关联键
ItemName | String | 现有 | — | 显示名称
ItemDiscription | String | 现有 | — | 描述文本
IconTexture | Texture2D | 现有 | — | 图标
ScenePath | String | 现有 | — | 场景资源路径
MaxStack | int | 现有 | — | 最大堆叠数；基础约束 MaxStack > 0
Products | Array | 现有 | — | 产物定义
Recipe | Array | 现有 | — | 配方定义
MainItemType | 枚举 | 现有 | — | 主类型
ItemType | 枚举 | 现有 | — | 子类型
GridSize | Vector2i | 新增 | Vector2i(1,1) | 网格占位尺寸；基础约束两轴均 > 0；旧资源需检查默认值
CanRotate | bool | 新增 | false | 是否允许 90° 旋转；false 时旋转被拒绝
1.2 功能设计
纯配置数据，无运行时状态方法；运行时代码仅只读访问。
建议提供校验函数 validate() -> bool：检查 GridSize 两轴均大于 0 且 MaxStack 大于 0，用于资源加载后校验。
旋转后尺寸的计算职责归属 GridService（不在 ItemConfig 上实现），以保持配置无状态。
2 ItemInstance（物品实例）
一个实例表示一个物品栈；数量不改变占位面积。位置与所属容器只在 InventoryContainer 记录中保存，实例内不设位置字段，避免双重数据源。
2.1 字段设计
[TABLE 5 rows]
字段 | 类型 | 说明与约束
instance_id | String | 运行时唯一 ID；跨容器完整转移保留 ID；拆分（后续功能）生成新 ID
config_id | String | 关联 ItemConfig.ItemID；写入前校验配置存在，缺失时拒绝写入（INVALID_ITEM）
quantity | int | 整数，1 ≤ quantity ≤ MaxStack；数量归零（空栈）时从容器移除
rotated | bool | 表达 0°/90°；false=0°，true=90°；旋转后有效尺寸交换两轴
2.2 功能设计
get_effective_size(config: ItemConfig) -> Vector2i
职责：读取配置占位尺寸，rotated 为 true 时交换 x/y。建议由 GridService 调用；SlotService 忽略。
参数：config：所属物品配置（供读取 GridSize）
返回：占位尺寸 Vector2i（旋转前为 GridSize，旋转后为 (GridSize.y, GridSize.x)）
is_empty() -> bool
职责：判断数量是否 <= 0；容器据此判定空栈并移除。
（堆叠相关，后续扩展）can_stack_with(other, max_stack) -> bool
职责：预留：同 config_id 且 quantity + other.quantity ≤ max_stack 时允许合并。基础版本不支持自动合并。
3 InventoryContainer（容器数据）
纯容器数据，由一个 Service 独占持有，不保存 Service 引用，不负责选择或创建服务。cells 记录实际占位，items 保存实例及锚点元数据，二者共同构成容器状态，必须在同一事务内更新。
3.1 字段设计
[TABLE 6 rows]
字段 | 类型 | 初始值 | 说明与约束
container_id | String | 初始化传入 | 容器唯一标识，也是 Manager 注册所属 Service 的路由键；非空且注册表内唯一，注册后保持不变
size | Vector2i | 初始化传入 | 矩阵宽高；x 为列数、y 为行数；两轴均大于 0；运行时扩容规则待细化
cells | Array(Array) | size.y 行 × size.x 列，全 null | 二维占位矩阵，按 cells[y][x] 访问；每格保存 instance_id 或 null；各行独立（避免浅拷贝共享行）
items | Dictionary | 空 | 按 instance_id 索引唯一记录 {instance: ItemInstance, anchor: Vector2i}；anchor 为左上角坐标；须与 cells 同一事务更新
revision | int | 0 | 版本状态；每次成功提交 +1；跨容器事务读取/校验版本以检测并发冲突（STALE_STATE）
3.2 功能设计
作为纯数据容器，仅提供内部辅助访问，不承载业务规则。
get_cell(pos: Vector2i) -> Variant
职责：返回 cells[pos.y][pos.x] 的 instance_id 或 null。
返回：instance_id（String）或 null
get_item(instance_id: String) -> Dictionary
职责：从 items 查询实例记录。
返回：{instance: ItemInstance, anchor: Vector2i}，不存在则返回空
snapshot() -> Dictionary
职责：返回只读快照：矩阵逐行深拷贝、items 中的实例可变字段独立复制，供暂存/回滚使用。
备注：避免浅拷贝提前修改原状态
4 InventoryService（抽象基类）
抽象基类，定义并独占持有 container，提供初始化、查询及操作契约，子类覆写规则。数据状态统一保存在 container 中，Service 不保存第二份状态。
4.1 字段设计
[TABLE 2 rows]
字段 | 类型 | 初始值 | 说明与约束
container | InventoryContainer | null | 独占持有；初始化前为 null，初始化成功后固定绑定；SlotService 与 GridService 继承该字段与初始化契约
4.2 功能设计
initialize(id: String, size: Vector2i) -> R
职责：创建并持有 InventoryContainer；初始化独立矩阵行与空物品表；全部成功后才绑定 self.container。
参数：id：容器 ID（非空、注册表内唯一）；size：矩阵尺寸（两轴 > 0）
返回：成功 OK；失败不绑定、container 保持 null
错误码：INVALID_POSITION（尺寸非法）、RULE_REJECTED（已绑定重复初始化）
query(pos: Vector2i) -> R
职责：只读查询位置物品；越界返回错误，空位无物品返回 ITEM_NOT_FOUND。
参数：pos：矩阵坐标
返回：OK，payload = {instance, anchor}；或 ITEM_NOT_FOUND / OUT_OF_BOUNDS
validate_add(item: ItemInstance, pos: Vector2i) -> R
职责：纯校验，不修改状态。校验实例有效、位置有效、占位不越界、目标为空。
返回：OK 或对应错误
错误码：INVALID_ITEM、INVALID_POSITION、OUT_OF_BOUNDS、OCCUPIED
add(item: ItemInstance, pos: Vector2i) -> R
职责：先 validate_add，通过后在同一事务写入 cells 与 items，revision +1。
参数：item：完整实例（含 instance_id/config_id/quantity/rotated）
返回：OK（changed=true）或错误
错误码：同 validate_add；已归属容器的实例不能重复加入
备注：添加/移除均针对完整实例
remove(pos: Vector2i) -> R
职责：点击任意已占格定位实例，清空其全部占位格并从 items 移除，revision +1。
返回：OK，payload 返回已脱离容器的实例（由调用方接管）；无物品 ITEM_NOT_FOUND
move(from_pos: Vector2i, to_pos: Vector2i) -> R
职责：在暂存状态中清空旧区域后验证新位置（允许新旧重叠），通过后提交。
返回：OK（changed=true）；相同位置 OK 且 changed=false
错误码：ITEM_NOT_FOUND、INVALID_POSITION、OUT_OF_BOUNDS、OCCUPIED
swap(a_pos: Vector2i, b_pos: Vector2i) -> R
职责：两端均需有物品；暂存移除双方、交换锚点、验证最终状态；任一放不下则保持原状。
错误码：ITEM_NOT_FOUND、OUT_OF_BOUNDS、OCCUPIED（换后冲突）
validate_plan(staged_state) -> R
职责：校验给定暂存状态是否满足全部不变量（占位规则、边界、items/cells 一致性），供跨容器事务在提交前整体验证。
返回：OK 或对应错误
4.3 跨容器事务内部能力（建议）
各 Service 提供内部暂存、提交和恢复能力，Manager 负责协调，不直接修改矩阵。
stage_snapshot() -> StagedState
职责：生成受影响状态的暂存副本；矩阵逐行复制，实例可变字段独立暂存。
备注：禁止浅拷贝，避免提前修改原状态
commit(staged: StagedState) -> R
职责：整体提交暂存状态并 revision +1；提交期间不 await、不触发 UI 回调、不运行外部玩法逻辑。
restore(snapshot) -> R
职责：提交异常时恢复事务前快照（矩阵、物品记录、数量、方向、版本号均回原值）。
备注：不要依赖“重新调用普通添加”回滚，避免再次触发规则失败
5 SlotService（普通背包）
继承 InventoryService，实现单栏占位：每个实例占一个格子，忽略物品网格尺寸，旋转不改变栏位占用。
5.1 字段设计
无新增持久字段，继承 container；规则为单格占位常量。
5.2 功能设计（覆写规则）
validate_add(item, pos) -> R
职责：检查二维坐标有效、目标格为空及实例有效；忽略 item 的 GridSize 与 rotated。
错误码：INVALID_ITEM、INVALID_POSITION、OCCUPIED
add(item, pos) -> R
职责：每个实例仅填写一个 cells[y][x]；同时写入 items（anchor = pos）。
move(from_pos, to_pos) -> R
职责：移动到空格成功，移到已占格失败（OCCUPIED）。
swap(a_pos, b_pos) -> R
职责：两端均需有物品，交换后仍各占一个格子。
6 GridService（网格背包）
继承 InventoryService，按旋转后的配置尺寸占矩形区域，校验边界、占用与冲突，维护锚点及占位索引的一致性。
6.1 字段设计
无新增持久字段，继承 container；占位规则按 config.GridSize 与 rotated 计算。
6.2 功能设计（覆写规则）
validate_add(item, pos) -> R
职责：根据 config 与 rotated 计算有效宽高，逐格验证边界与矩阵占用。
错误码：INVALID_ITEM、OUT_OF_BOUNDS、OCCUPIED
add(item, pos) -> R
职责：占位范围 [x, x+w) × [y, y+h)，多格填写同一 instance_id；items 与 cells 同一事务更新。
move(from_pos, to_pos) -> R
职责：在暂存矩阵中清空该实例旧区域，再验证新位置，因此允许新旧区域重叠；越界或撞到其他物品保持原状态。
swap(a_pos, b_pos) -> R
职责：暂存中移除双方占位，A 放到 B 原锚点、B 放到 A 原锚点，再检查最终区域与所有其他物品、以及双方新区域是否相互重叠；任一校验失败不改原状态。
7 InventoryManager（统一入口）
维护 container_id → InventoryService 注册表，选择服务类型并初始化，提供统一操作与只读查询，协调跨容器事务与成功通知。建议作为 Autoload Node。
7.1 字段设计
[TABLE 4 rows]
字段 | 类型 | 说明
containers | Dictionary | container_id → InventoryService 注册表；路由键；只接受已初始化且未被其他注册项绑定的 Service
transaction_lock | bool | 跨容器事务锁；事务期间禁止注销/替换参与 Service、禁止重入
signals | 信号 | container_changed(container_id, revision, changed_ids)、operation_failed(code, message)
7.2 注册与查询
create_container(id: String, size: Vector2i, service_type: ServiceType) -> R
职责：校验 ID 非空/不重复、尺寸两轴大于零、类型受支持，创建对应 Service 并调用 initialize；全部成功才注册。
返回：OK 或错误
错误码：DUPLICATE_CONTAINER、INVALID_POSITION、UNSUPPORTED、INTERNAL_ERROR
备注：服务类型初始化后固定；运行时切换须另行设计迁移
register_container(id: String, service: InventoryService) -> R
职责：注册已初始化且未绑定的 Service。
错误码：DUPLICATE_CONTAINER、RULE_REJECTED（未初始化）
unregister_container(id: String) -> R
职责：注销并释放 Manager 对 Service 的引用；未知 ID 返回 CONTAINER_NOT_FOUND；事务期间禁止注销。
备注：关闭 UI 不注销玩法仍需使用的 Service
get_item_at(id: String, pos: Vector2i) -> Dictionary
职责：只读查询位置物品。
返回：{instance, anchor} 或空
错误码：CONTAINER_NOT_FOUND、OUT_OF_BOUNDS、ITEM_NOT_FOUND
get_snapshot(id: String) -> Dictionary（建议）
职责：返回容器只读快照/DTO；不暴露可写 Dictionary 或可写 ItemInstance。
7.3 容器内操作
add_to_container(id: String, item: ItemInstance, pos: Vector2i) -> R
职责：路由到对应 Service.add；必须接收待放入实例（仅 ID 与位置不足以描述添加对象）。
错误码：CONTAINER_NOT_FOUND、INVALID_ITEM、INVALID_POSITION、OCCUPIED
remove_from_container(id: String, pos: Vector2i) -> R
职责：路由到 Service.remove；移除成功后 payload 返回脱离容器的实例，由调用方接管。
move_in_container(id: String, from_pos: Vector2i, to_pos: Vector2i) -> R
职责：路由到 Service.move；相同位置返回 OK 且 changed=false。
swap_in_container(id: String, a_pos: Vector2i, b_pos: Vector2i) -> R
职责：路由到 Service.swap。
can_place(id: String, item: ItemInstance, pos: Vector2i, rotated: bool) -> R
职责：预览校验，不修改状态；提交时仍会重新校验。
备注：预览通过不等于最终提交成功
7.4 跨容器事务
switch_to_container(from_id: String, to_id: String, f_pos: Vector2i, t_pos: Vector2i) -> R
职责：完整转移：源实例移出并放入目标；目标被占用则失败（OCCUPIED），不隐式交换或合并。
错误码：CONTAINER_NOT_FOUND、ITEM_NOT_FOUND、OUT_OF_BOUNDS、OCCUPIED、STALE_STATE
备注：同一容器 ID 的转移转发为 move_in_container；跨类型转移保留实例方向
swap_between_containers(a_id: String, b_id: String, a_pos: Vector2i, b_pos: Vector2i) -> R
职责：双方实例交换：暂存移除双方实例，按目标 Service 规则验证完整最终状态后提交。
错误码：CONTAINER_NOT_FOUND、ITEM_NOT_FOUND、OUT_OF_BOUNDS、OCCUPIED、STALE_STATE、INTERNAL_ERROR
7.5 事务流程与通知
流程：从注册表取双方 Service → 定位容器、解析源实例与目标锚点、记录双方 revision → 检查仍注册且禁止重入 → 创建暂存副本/变更计划 → 校验通过且版本未变 → 协调双方 Service 提交 → 成功后 revision 更新并发送通知。
提交期间不 await、不触发 UI 回调、不运行外部玩法逻辑。
任一提交异常：要求双方 Service 恢复事务前快照，返回 INTERNAL_ERROR。
成功事务提交全部状态后发 container_changed(container_id, revision, changed_ids)；失败只发 operation_failed(code, message)，不发内容变化通知；单容器单事务只增加一次 revision。
8 InventoryUI（表现层）
将点击、拖拽、旋转意图转成 Manager 调用；只维护视图状态，不得直接修改数量、坐标或占位。
8.1 字段设计
[TABLE 5 rows]
字段 | 类型 | 说明
manager | InventoryManager | Manager 引用，所有读写经此入口
selected | Dictionary | 当前选中项视图状态：{container_id, pos, instance}（可能为空）
drag_preview | Dictionary | 拖拽预览状态：{from_pos, current_pos, rotated}（仅视图，不写入容器）
snapshot_cache | Dictionary | 本地只读快照缓存，收到通知后刷新
8.2 功能设计
on_cell_click(container_id, pos)
职责：点击已占格：经 get_item_at 查询并高亮实例（GridService 下点击任意占位格定位到同一实例及锚点）。
on_drag_start(container_id, pos)
职责：记录拖拽来源并生成预览；仅更新视图状态，不改容器数据。
on_drag_move(pos)
职责：更新拖拽预览位置；如需占用提示调用 can_place 预览校验。
on_drag_drop(target)
职责：转成 Manager 调用（move/switch/swap，视上下文）；失败时保留原视图。
on_rotate()
职责：切换拖拽预览的旋转状态；CanRotate 为 false 时拒绝旋转。
on_drag_cancel()
职责：清理 UI 预览；预览阶段未改变容器数据，无需回滚。
refresh()
职责：收到 container_changed 后重新经 Manager 查询并刷新界面。
show_result(code, message)
职责：根据结果 code 显示本地化反馈；operation_failed 信号触发。
9 附录：始终成立的基础约束
同一实例最多属于一个容器；每格最多记录一个实例 ID；矩阵内所有非空 ID 必须存在于 items。
每条 items 记录在矩阵中的覆盖必须恰好符合当前 Service 的占位规则；所有占位都在边界内。
操作失败时矩阵、物品记录、数量、方向、位置和版本号均保持原值。
跨容器转移前后总数量守恒。
SlotService 对任意 size 均每实例占一格；GridService 多格填同一 instance_id。普通背包使用二维坐标，一维栏位可初始化为 Vector2i(capacity, 1)。
