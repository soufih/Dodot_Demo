# 快速添加接口与测试说明

## 接口

Service 抽象契约：

```gdscript
quick_add(item: ItemInstance) -> InventoryResult
```

由 `SlotService`、`GridService` 实现；调用方可持有统一的 `InventoryService` 类型。
Manager 对外入口：

```gdscript
quick_add_to_container(id: String, config_id: int, quantity: int = 1, rotated: bool = false) -> InventoryResult
```

用法：

```gdscript
var result := InventoryManager.quick_add_to_container("旅行背包", 1004, 3)
if result.is_ok():
    var anchor: Vector2i = result.payload
    print("实际放置位置：", anchor)
else:
    print(result.message)
```

## 查找与提交规则

从左上角开始，先从左到右扫描一行，再从上到下扫描下一行。
找到第一个能完整放入物品的位置后立即提交，成功时 `payload` 返回实际锚点 `Vector2i`。

普通背包每个实例栈占一格，保留方向元数据。
网格背包先按物品当前方向扫描全部位置，跳过碰撞或越界位置。
若该方向无适配位置，且配置允许旋转，则翻转方向后重新从左上角按行查找。
当前方向存在位置时优先使用，即使旋转后可能放在更靠前的空位也不会提前旋转。
方形物品无需重复扫描。非法实例、配置规则或提交错误不触发方向重试。

整栈独立放置，保留实例 ID、配置及数量；自动旋转只作用于实例副本，
传入的物品对象保持不变，容器保存最终放置方向。两个方向都没有适配位置时不提交状态。

无论成功或失败，都沿用现有添加规则。不存在完整适配位置时返回 `NO_SPACE`；
非法实例、重复实例、未初始化、禁止旋转或未知容器，返回对应的原有错误码。
查找失败不改变容器、输入实例和版本。提交失败沿用快照恢复机制。

Manager 根据配置 ID、数量和首选方向创建具有新 ID 的实例，在事务锁内调用具体服务。
已有物品保留身份的移动应使用转移接口，快速添加始终表示新增物品。
一次成功只增加一次容器版本并发送一次变更通知，失败不发送内容变更通知。

## Lab 接入

`Scene/Inventory/InventoryLab.tscn` 的添加物品表单现使用快速添加。
选择目标容器、物品、数量及首选方向后点击“快速添加物品”，通过 Manager 自动选择位置，
状态栏显示实际放置坐标；无适配位置时显示失败原因。
表单已移除手动 X/Y 坐标控件，默认演示物品也通过快速添加入口放入。
“优先旋转 90° 放入”表示首选方向；网格背包在该方向放不下时仍会尝试另一方向。
物品视图从最新快照读取实际方向，不改变表单的首选设置。

## 测试内容与方法

新增 `tests/inventory/quick_add_spec.gd`，接入现有领域测试 runner。

| 测试内容 | 验证方法 |
| --- | --- |
| 普通背包首个空格、跨行顺序、单格占位、栈数量与方向 | 固定占位夹具，经抽象服务调用，检查返回锚点、记录及矩阵 |
| 网格完整矩形、旋转方向、边界恰好适配 | 预置障碍，验证跳过不适配锚点并优先选择当前行合法区域 |
| 自动旋转回退、首选方向优先、禁止旋转 | 验证两个初始方向的回退、碰撞回退，以及当前方向下一行位置优先于旋转后的更早空位 |
| 空格总数足够但零散、尺寸不适配、背包已满 | 断言 `NO_SPACE`，比较操作前后完整快照 |
| 非法实例、重复实例、禁止旋转和未初始化 | 检查准确错误码，确保未被无空间错误覆盖 |
| Manager 按值创建、路由及通知 | 通过配置 ID 与数量调用统一入口，检查新身份及成功/失败通知 |
| 提交后失败、过期版本和事务重入 | 用现有 FaultService 注入故障，验证恢复、版本保持、拒绝重入及成功重试 |
| 自动旋转后的提交失败、过期版本与成功重试 | 验证保留原错误码、恢复完整状态、不修改输入方向且仅通知一次 |
| Lab 表单接入 | `tests/inventory/ui_spec.gd` 通过按钮验证连续添加、自动旋转后的占位与视图、首选方向保持、坐标提示及无空间失败 |

运行：

```powershell
.\tests\inventory\run-tests.ps1 -IncludeUI
```

测试结果以运行日志中的完成标记为准。
日志位于 `Log/inventory-tests.log` 与 `Log/inventory-ui-tests.log`。
