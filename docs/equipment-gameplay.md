# 装备系统正式玩家接入

## 运行与操作

真实 `Hero.tscn` 已通过场景节点接入装备组件。进入游戏后，按 Tab 同时打开玩家背包与装备栏；将合法装备拖入对应槽位穿戴，拖回背包卸下，拖到已占用槽位进行事务交换。不含仓库时，窗口初始位置由工作区的 `window_positions` 数组与 `WindowPositions/WithoutWarehouse` 定位点依次指定；包含仓库时整套切换到 `warehouse_window_positions` 数组与 `WindowPositions/WithWarehouse`。较小分辨率会等比适配完整窗口，内部手工布局保持不变。

主武器与副武器都装备时，按项目现有的 Q 键切换当前使用的武器。切换只改变角色的使用选择，不移动装备实例、不递增容器版本。卸下当前武器后，会选择剩余的第一个非空武器槽；全部卸下则回到空手。

`Hero.tscn` 的 InputController 通过导出的 `equipment` 引用本角色装备组件。真实攻击输入仅在 `get_current_weapon() != -1` 时缓存并发出攻击请求；空手或未绑定装备组件时不发出请求。背包等界面打开期间继续由原有输入禁用逻辑屏蔽攻击，关闭后左键经状态机进入 Attack，由武器控制器播放当前武器动画。

可直接运行 `Scene/Inventory/InventoryGameplayLab.tscn`。场景按钮可生成长剑、备用武器和双手弓，靠近掉落按 E 拾取，再按 Tab 拖放穿戴。测试台的重置按钮会同时重置背包和装备。

## 数据与职责

| 模块 | 职责 |
|---|---|
| `Rescource/Data/Inventory/player_equipment.tres` | 正式玩家装备定义，独立于演示定义；包含八个业务槽位 |
| `PlayerEquipmentComponent` | 创建或复用装备会话，选择当前与备用武器，监听 Manager 成功提交 |
| `PlayerInventoryComponent` | 拾取物品进入背包，打开背包和装备的双窗口；显式开始新会话 |
| `EquipmentSlotService` | 类型适配、双向互斥、数量及完整计划校验 |
| `InventoryManager` / `InventoryTransaction` | 唯一物品归属、原子转移和交换、版本与提交后通知 |
| `WeaponController` | 使用装备组件选择的正式物品，查询已有武器属性、更新手持图标与攻击上下文 |
| 武器 HUD | 从角色装备组件读取当前和备用武器图标，保留原有切换表现 |

`Hero.tscn` 中的 Equipment、Inventory、WeaponController 和武器 HUD 通过导出的节点引用连接，不创建第二个装备全局单例。所有 UI 及新增测试按钮均通过 `.tscn` 搭建。

已替换武器控制器、HUD 和切换状态对已停用 `EquipmentSlotSystem` 的读取。装备变化只在 Manager 提交后传播；失败穿戴不会改变武器选择或战斗属性。更换武器时清理旧攻击上下文，异步动作恢复后检查武器代次，避免继续驱动新武器。

## 正式物品配置

物品通过 `ItemConfig.Equipment.equipment_type` 声明装备类型，现使用 `ENUM.EquipmentType` 枚举。剑类（10、11、12）可配置为 `ONE_HAND`，法杖和弓类（13～16）可配置为 `TWO_HAND` 并在 `blocked_slot_ids` 中声明 `off_hand`。当前正式物品目录中的这些武器尚未配置 `Equipment`，需要在检查器中创建 `EquipmentItemConfig` 并选择枚举类型后才能穿戴；仅填写物品主类型或修改背包占格不会补齐该规则。

战斗效果继续使用 `WeaponManager` 中已有的武器属性，按正式物品名称关联。当前目录已存在剑与弓的攻击属性；只有物品配置而缺少对应武器属性的装备不会凭空获得攻击能力。

头部、身体和四个饰品槽可按既有装备规则存放、穿脱物品。正式物品目录尚未配置的防具或饰品，需要作者添加对应 `EquipmentItemConfig`。本次没有新增伤害加成、防御、套装等角色属性规则。

## 会话与生命周期

- 关闭界面、角色死亡和切换场景均不删除装备实例。
- 新角色复用原 Manager 中的装备容器，并重新绑定武器控制器和 HUD；初始使用选择按 `weapon_slots` 配置顺序优先采用第一个非空槽位。
- 旧角色退出解除订阅，避免重载场景后重复通知。
- 主菜单“新游戏”显式重建背包与装备两个容器。正式测试台的重置按钮通过玩家组件重置两者，并清空武器与 HUD。
- 当前为运行期会话数据，尚未增加磁盘存档。

## 测试方法

```powershell
.\tests\inventory\run-tests.ps1 -EquipmentOnly -IncludeEquipmentUI -IncludeEquipmentGameplay
```

首次新增脚本可先在 Godot 编辑器中刷新文件，或使用脚本的 `-Import` 参数。

新增 `tests/inventory/equipment_gameplay_runner.tscn` 与 `equipment_gameplay_spec.gd` 使用正式玩家场景、正式资源、真实物理拾取和 `Input.parse_input_event()` 键鼠输入。验证内容：

键鼠回归在运行期清空测试工作区的定位点数组，使用独立的并排窗口夹具，避免作者手工调整窗口重叠后遮挡测试落点。正式场景中的定位点资源不会被修改，定位数组本身由装备 UI 套件单独验证。

1. 玩家自动创建八槽装备会话，背包引用装备组件，新会话空手。
2. 真实 E 拾取；Tab 打开两窗口；窗口并排不重叠。
3. 原生拖放穿戴保留实例身份，正式攻击属性、手持图标与 HUD 同步更新。
4. 1280 × 720 下装备窗口完整可见，缩放后仍能正确拖入副武器槽。
5. Q 经原状态机切换武器，容器实例与版本不变。
6. 双手与副武器双向互斥，失败时两个容器和当前武器保持不变。
7. 卸下当前武器自动回退，关闭窗口取消原生拖放。
8. 实际重载玩家场景保留双方完整快照，旧组件释放且订阅数量不增加。
9. 重置同时清空两个容器、攻击属性、上下文与 HUD。
10. 真实鼠标左键验证空手不请求或缓存攻击；穿戴后背包打开期间仍屏蔽攻击；关闭背包后进入 Attack、使用正式武器属性播放 SwordAttack，动画自然结束后退出攻击状态。该流程不再直接发送角色攻击信号来绕过输入和状态机。

本次枚举迁移结果：装备服务 **300 条断言，0 失败**，装备 UI **178 条断言，0 失败**。正式装备接入测试在首次穿戴处失败退出，原因是当前正式物品目录中武器的 `Equipment` 为空；本次没有自动为普通或未配置物品指定装备类型。补齐资源后再运行上述完整命令，才能验证后续真实攻击、切换和场景生命周期流程。

原有全量领域和 UI 回归中的旋转默认值预期差异，及旧拾取集成夹具对正式资源尺寸的固定假设，不通过修改正式物品配置来规避；它们与本次新增的独立接入回归分别报告。
