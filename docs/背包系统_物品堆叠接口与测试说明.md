# 物品堆叠接口与测试说明

## 行为规则

同配置 ID 的两个物品栈可以合并，实际转移数量为
`min(源数量, MaxStack - 目标数量)`。目标实例 ID、锚点、方向和占位保持原值。
源有余量时保留原实例 ID、锚点、方向及占位；源耗尽时删除记录并释放全部占位。
例如，上限为 10 时，将 7 件拖到已有 8 件的栈上，合并 2 件，源剩余 5 件。

不同配置、目标已满及 `MaxStack = 1` 时返回 `RULE_REJECTED`。
坐标非法、空位置、无效实例和未知容器使用现有对应错误码。
对同一实例执行正式堆叠返回成功、`payload = 0`、`changed = false`。
不同方向不影响堆叠兼容性；网格容器支持通过任意占位格定位双方锚点。

## 接口与分工

`InventoryService` 保持抽象类，只声明接口。操作实现在
`SlotService` 和 `GridService` 中，公用数量校验由无状态的
`InventoryStateOps.validate_stack` 提供。

| 层级 | 接口 | 说明 |
| --- | --- | --- |
| Service | `stack(from_pos, to_pos)` | 同容器堆叠并一次性提交 |
| Service | `can_stack(item, pos)` | 只读预览目标可接收数量 |
| Service（内部） | `stage_stack(staged, item, pos)` | 仅增加暂存目标数量，返回接收数量；不扣减输入实例 |
| Manager | `stack_in_container(id, from_pos, to_pos)` | 路由同容器堆叠 |
| Manager | `stack_between_containers(from_id, to_id, from_pos, to_pos)` | 跨容器原子堆叠；ID 相同时转为同容器操作 |
| Manager | `can_stack(id, item: ItemInstance, pos)` | 按传入实例预览目标可接收数量，不修改真实状态 |

接口均返回 `InventoryResult`。堆叠及预览成功时，`payload` 为实际或预计接收的整数数量。
预览不提交状态，正式执行时重新读取源数量和目标容量。

跨容器操作复用 `InventoryTransaction` 的快照、校验、版本检查、同步提交及回滚流程。
数量调整与矩阵写入经 Service 暂存接口执行。任一提交失败则恢复双方完整快照；
双方提交完成后才发送 `container_changed`，每个发生变化的容器版本只增加一次。

```gdscript
var result = InventoryManager.stack_between_containers(
    "旅行背包", "储物箱", Vector2i(0, 0), Vector2i(0, 0))
if result.is_ok():
    print("合并数量：", result.payload)
```

## UI 操作

- 普通拖到空格：移动物品。
- 普通拖到同类可堆叠物品：自动按剩余容量堆叠，无需 Shift，余量留在原位置。
- 普通拖到不同物品或不可堆叠物品：执行交换。
- 同类目标栈已满：不接受默认堆叠拖放，双方保持原状。
- 按住 Shift 拖到已有物品：强制交换，包括同类物品和满栈。
- 拖到自身任意占位格：无变化；交换后任一物品放不下时，双方保持原状。

画板通过 Manager 预览和提交，不直接修改数据。成功合并后选中保留身份的目标栈，
更新双方数量视图、选择说明及状态栏实际合并数量。现有 UI 控件继续由 `.tscn` 声明。

## 测试内容与方法

| 文件 | 内容 | 方法 |
| --- | --- | --- |
| `tests/inventory/stack_spec.gd` | 两类服务的部分/完整合并、方向与非锚点、源占位释放、输入及快照隔离 | 独立配置夹具，通过抽象契约调用，比较数量、矩阵、实例字段及版本 |
| 同上 | 错误分支、同一实例无变化、满栈、不兼容、不可堆叠、非法坐标及实例 | 比较操作前后完整快照，检查错误码及 `changed` |
| 同上 | SLOT→SLOT、SLOT→GRID、GRID→SLOT、GRID→GRID | 通过 Manager 集成调用；在首次通知中检查双方已经提交 |
| 同上 | 部分/完整堆叠的本地及跨容器回滚、过期事务及重入 | 使用现有 FaultService 注入提交后失败、版本变化及校验回调，检查快照与通知 |
| 同上 | 数量守恒与容量边界 | 对两类服务各穷举源/目标数量 1～10，共 200 个组合 |
| `tests/inventory/ui_stack_spec.gd` | 网格/栏位内及跨类型默认堆叠、数量文字、选择目标、满栈取消、Shift 强制交换 | 默认不按修饰键注入真实鼠标拖放，强制交换用例才按住 Shift，读取实际 Label 和容器状态 |
| 同上 | 预览只读、预览之后目标被填满、不兼容与不可堆叠预览 | 预览后通过合法命令改变目标，再正式释放，验证重新校验及失败原子性 |
| 同上 | 普通拖放：同类未满栈自动堆叠，不同物品和不可堆叠物品交换，跨类型非锚点、自身和放不下的失败 | 真实鼠标输入，不按 Shift；比较双方实例 ID、数量、锚点、版本和选择状态 |

运行全部领域和 UI 回归：

```powershell
.\tests\inventory\run-tests.ps1 -IncludeUI
```

手动检查可运行 `Scene/Inventory/InventoryLab.tscn`。
默认两个容器各有一栈卷轴，可直接拖放验证跨容器合并，按住 Shift 拖放验证强制交换；
也可通过左侧添加物品表单准备接近上限的栈，验证堆叠余量保留。
自动测试使用独立夹具，不依赖默认演示物品。

日志分别写入 `Log/inventory-tests.log` 与 `Log/inventory-ui-tests.log`。
脚本同时检查进程退出码、Godot 错误日志和零失败完成标记。

测试结果以本次运行日志中的完成标记为准。
